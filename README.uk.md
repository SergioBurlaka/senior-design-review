Лінтери й аудити доступності скажуть, що контраст 3.1:1. Вони не скажуть, що застосунок
*виглядає як зроблений розробником*, що червоний означає три різні речі, що кнопка видалення
важить більше за дані або що мобільна версія — це десктопна сторінка, стиснута до 375 px.

Цей скіл скаже. Він відкриває запущений застосунок у справжньому браузері, емулює телефон і
десктоп, вимірює все, що можна виміряти, а решту оцінює як сеньйор-дизайнер — у тому контексті,
в якому продуктом реально користуються.

## Що ви отримуєте

Звіт, що читається як дизайн-критика, а не чекліст:

- **Вердикт** — що вдалося, що найбільше стримує, наскільки далеко до відчуття «зроблено з думкою».
- **Скоркарта** — по осях (ієрархія, типографіка, відступи, колір, стани, мобайл, десктоп,
  ідентичність, доменна відповідність). Загальної суми немає.
- **Топ-пріоритети** — за співвідношенням користі до зусиль.
- **Знахідки** — твердження, чому це важливо *саме тут*, докази, порушений принцип,
  severity 0–4 за Нільсеном, зусилля S/M/L, рекомендація «до → після» і підстава:
  `виміряно` (число проби), `видно` (названий скріншот) або `судження` (аргументована думка).
- **Що працює добре** і **що перевірити на реальному пристрої**.

Справжній приклад: [рев'ю MyGym](examples/sample-report-mygym.md).

Потім другий погляд — з крісла арт-директора і очима реального користувача. |

| **Ваш стандарт** | Якщо в репозиторії є `DESIGN_PRINCIPLES.md`, його правила вищі за дефолти скіла, і кожна знахідка посилається на порушене правило. [Шаблон](skills/senior-design-review/assets/DESIGN_PRINCIPLES.template.md) додано. |

## Встановлення

### Claude Code

```bash
claude plugin marketplace add SergioBurlaka/senior-design-review
claude plugin install senior-design-review@sergioburlaka
```

Або в сесії: `/plugin install senior-design-review --marketplace SergioBurlaka/senior-design-review`.

Оновлення: `claude plugin update senior-design-review@sergioburlaka`.

**Рекомендовано:** справжня мобільна емуляція через Chrome DevTools MCP:

```bash
claude mcp add chrome-devtools --scope user -- npx chrome-devtools-mcp@latest --autoConnect
```

### Застосунки Claude (claude.ai, десктоп, мобільний)

1. Завантажте `senior-design-review.zip` з [останнього релізу](https://github.com/SergioBurlaka/senior-design-review/releases/latest).
2. У Claude відкрийте **Customize → Skills**, натисніть **Add** і завантажте zip (виконання коду має бути увімкнене).
3. Увімкніть скіл.

У десктопному застосунку Claude скіл керує вбудованим браузером; його мобільний пресет емулює
мобільний user agent і `pointer: coarse`.

### Просто папкою

Скопіюйте `skills/senior-design-review/` у `~/.claude/skills/` (для всіх проєктів) або в
`.claude/skills/` одного репозиторію.

## Використання

Просіть своїми словами — скіл спрацьовує на запит про дизайн-рев'ю:

```text
Зроби дизайн-рев'ю https://staging.myapp.com на десктопі й мобайлі
Чи виглядає наш checkout професійно? Чесно.
Подивись очима дизайнера тільки екран Прогрес, мобайл
Я виправив F02–F05 — перевір ці місця ще раз і порівняй з минулим звітом
```

Поради:

- **Застосунки з логіном.** Скіл ніколи не вводить ваш пароль. Увійдіть самі в браузері, яким він
  користується (DevTools MCP з `--autoConnect` чіпляється до вашого Chrome), або один раз збережіть
  сесію: `python3 skills/senior-design-review/scripts/capture.py --login <url> --storage-state auth.json`. Краще тестовий
  акаунт — усе, що на екрані, потрапляє в контекст моделі.
- **Флоу, що пишуть дані** (оплата, старт тренування), скіл проходить лише на тестовому акаунті
  або з вашої згоди; інакше вони йдуть у звіт як «не перевірено».
- **Локальні dev-сервери** теж працюють, і це найбезпечніше місце для таких флоу.

## Розробка

```bash
pip install playwright pytest pyyaml && python -m playwright install chromium
pytest tests                              # регресійні тести проб
claude plugin validate --strict .         # маніфести
python3 scripts/build_release.py          # dist/senior-design-review.zip
```

Реліз: підніміть `version` у `.claude-plugin/plugin.json`, додайте запис у `CHANGELOG.md` і
поставте тег `vX.Y.Z` — workflow збере архіви й опублікує GitHub Release.

Внески вітаються, особливо нові **доменні модулі** (e-commerce, дашборди, бронювання, контент):
скопіюйте `references/domain-fitness.md`, збережіть його розділи і додайте тест на фікстурі для
кожної нової перевірки в пробі.

## Обмеження

- Емуляція — це Chromium. Особливості iOS Safari (`100vh`, зум полів, safe-area на справжньому
  вирізі, PWA standalone) потребують реального пристрою; звіт виносить їх окремим списком.
- Severity від одного рецензента — це оцінка. Сприймайте звіт як сильну другу думку, а не вердикт
  вашої дизайн-команди.

## Приватність

У плагіна немає сервера, і він нічого не надсилає ні автору, ні стороннім сервісам. Він читає сторінки, які ви просите відрев'юїти; деталі — у [PRIVACY.md](PRIVACY.md).
